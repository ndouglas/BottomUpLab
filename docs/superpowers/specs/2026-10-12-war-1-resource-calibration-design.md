# W1-A conservative batched resource calibration

Date: 2026-10-12. Status: **engineering design for review only**. This document does not amend the running forecast, admission gates, protocol, scientific population or authorization. Implementation requires written user review, a later implementation plan and independent review. No new measurements are authorized by this draft.

## Problem and choice

The current [`forecast`](../../../survey/war1_study/resource_proof.py) multiplies the largest measured kernel seconds/actor-step by every initial actor-step, the largest projection seconds/step by every settlement, and separately charges case, audit, byte and source costs before applying 4×. All sixteen fixed construction cases must be present. This conservative forecast remains operative.

The independently reviewed native-SHA preparation attempts produced 27.7898, 56.6060 and 15.1612 guarded hours with unchanged code and roughly 64.17–64.27 s whole diagnostic CPU. All failed the existing 12 h guard. Private observer diagnostics gave approximately 17–7542 ratios between maximum extrapolation and aggregate measured spans; the denominator and work scope differ from a campaign forecast. These observations justify investigating normalization and timing sensitivity, not declaring the old proof invalid or substituting private costs for admission. Whole actual-collector CPU (0.70–1.36 s) was far below its 13.65–16.61 s wall; CPU improvements alone cannot establish wall feasibility. Retained evidence paths and limitations are listed in the accompanying design-source notes.

Choose a **nonnegative inclusive process-CPU envelope over batches**, with a separate phase/event ledger and stratified eligibility checks. Retain an explicit fixed settlement term alongside actor and byte terms. Do not select a favorable maximum/percentile, divide an early-ending run by unexecuted work, or treat p95 as an upper bound. A direct per-arm empirical forecast is unsuitable with the current eight fixture configurations: it would require unapproved new workloads and would still not cover every possible trajectory.

This is an empirical conservative forecast within a declared engineering domain, not a performance theorem for all seeds, hosts or storage delays. If required coverage cannot be established within authorized fixtures, resource readiness remains unavailable.

## Proposed cost equation

For each disjoint accounting phase p and predeclared coverage stratum z, record a batch feature vector

`x = (N, Q, I, S, A, A0, L, C, V, F, D)`.

N counts fixed phase invocations (campaign launches or case setup/end as specified in the ledger); Q is a vector of operation counts (file open/stat/read/hash, append, finish, metadata save and validation row). Each actual invocation increments its named Q entry, including repeat passes; Q cannot be replaced by bytes or file uniqueness. I is initial actors summed over case setup invocations, distinct from A0 per-settlement work. S counts actual settlements; A counts actual live actors at settlement start summed over steps; A0 is initial population summed over steps; L is the integer upper feature `sum n·ceil(log2(max(n,2)))` over relevant steps; C counts processed casualty entries; V is bytes serialized/hashed/read/written **in that phase**, including repeated encoding and nested strings; F counts file syncs; D counts directory syncs. Use integer counters throughout. Idle/empty phases have zero work; fixed setup has its own invocation count. Maintain phase-specific feature masks so a byte/sync operation is not silently assigned to another phase.

Define a nonnegative linear envelope `E[r,z](x)=theta[r,z]·x`, with each Q entry having its own coefficient. For CPU, r denotes an inclusive process group (native collector or Python supervisor), **not a kernel/projection phase**. Phase masks/counters explain work coverage; they cannot identify phase CPU from whole-process timing. For direct elapsed IO/T measurements only, r may denote a separately measured nonoverlapping phase. Fixed frame parsing/accounting/hash setup belongs in the S coefficient, not a large per-actor ratio induced by a near-extinction denominator. Actor-dependent checkpoint cloning/validation belongs in A. The duel kernel allocates membership over the **initial** population each step; aimed fire also resizes membership to initial population on casualty-bearing steps. Conservatively charge A0=nK for **both geometries**. Accounting allocates its initial-population alive vector once per case; charge I in its setup phase mask. Replacing this work by current live actors would omit cost. Casualty set/ordering costs justify L/C coverage. This feature list is a conservative candidate, not an asserted asymptotic complexity proof; source review can require a new term or finer stratum before fitting.

For the scientific census, use full horizon K and initial n for every case: `I_i=n_i`, `S_i=K_i`, `A_i=A0_i=n_i K_i`, `L_i=K_i n_i ceil(log2(max(n_i,2)))`, `C_i≤n_i`. Projection byte bounds must cover frame serialization **on every step**, even without retained audit, and initial/final checkpoint and four observations. Audit envelopes add audited S and bounded nested-serialization bytes. Native archive append currently encodes once for budget/prefix and again in `Journal::append`; preserve that work in V. Bound survivor/casualty-dependent dimensions independently, conservatively allowing mutually exclusive maxima if necessary. Never derive scientific savings from the particular endings at seeds 7/8.

A case's reachable work domain includes its geometry, initial population and every lower current-population band, casualty branch, rate/dt/profile and byte/event extreme. Initial-population and current-population axes remain distinct. For each case i build phase-specific full-horizon upper vectors U[i,p], then sum them with campaign setup/closure vectors to X*. For each process CPU group use the componentwise maximum coefficient vector across **all required, covered** strata before evaluating X*. For IO/elapsed phases sum `max_z E[p,z](U[i,p])` across cases and campaign-only phases. If any reachable stratum is uncovered, the computation returns unavailable before producing a forecast; no measured occupancy weighting or favorable stratum selection.

| Eligibility axis | Existing fixture support | Full-campaign eligibility rule |
|---|---|---|
| Geometry | Both geometries | Both and their distinct branches must be covered |
| Initial total population | 2, 3, 128, 768 | Missing intervening roster populations require reviewed source domination or separately authorized coverage; endpoint timing alone is insufficient |

| Bytes/file/events | Synthetic128 short writes+reads and four16MiB source files | Cover row/metadata maxima,4096 source files, all opens/stats/sync/finish/reread counts independently; present fixtures alone do not establish this |
| Process stages | Native fixture and separate synthetic child | Complete native and Python preflight/postflight/terminal windows required; child-only holdout insufficient |

This draft establishes **no full-campaign coverage or admissible coefficients**. Repetitions/two batch sizes measure noise/scaling but do not add rank to proportional feature rows, cover unseen trajectories or repair missing structural dimensions. Pinned rand0.8.8 shuffle uses uniform rejection sampling; live-actor counts do not deterministically bound RNG words. Seed/geometry-dependent tails remain an empirical coverage limitation and hard-monitor stop risk, not a reason to change RNG/model or open registered seeds.

Inclusive sampled stacks or whole-child CPU cannot be summed with included phase costs. If a phase boundary cannot be measured without overlap, charge the larger inclusive span and label intentional double counting; never subtract an unmeasured residual to improve the forecast.

## Calibration and wall allowance

Select the boring inclusive CPU observable: native collector response is its complete wait4 user+system CPU, from launch through exit, including runtime initialization, all kernel/observer/archive work, counter overhead, closure and destruction. Python supervisor response is `getrusage(RUSAGE_SELF)` user+system delta spanning entry to `supervise` through return, including `_inputs`, receipt/manifest parsing, channel/log/resource work, source verification, original archive validation and terminal publication. Parent SELF excludes waited children; separately record every launched child PID/command/wait4 usage exactly once, including native metadata, git and `/bin/ps` sampling subprocesses, and add their inclusive CPU in a third auxiliary-process group excluding the already counted collector PID. Process-tree evidence must show each wait4 group has no unaccounted descendants or supply a reviewed platform-specific inclusion/deduplication rule. Reject missing reaps or ambiguous descendant scope; never add cumulative RUSAGE_CHILDREN atop per-child totals. Python import/startup and process shutdown outside the function receive a separately measured launch/teardown CPU allowance or remain an explicit unavailable setup cost. Counter/timer collection overhead stays inside responses; no subtraction. These are prospective observables, not present instrumentation. Parent CPU and complete wall/RSS evidence are prerequisites, not derivable from old collector-child receipts.

CPU* is the sum of inclusive native, parent-SELF, auxiliary-child and launch/teardown CPU envelopes; **no kernel/projection/audit/closure phase CPU terms are added**. Phase Instant elapsed spans remain diagnostics and direct IO elapsed measurements where independently scoped. Do not allocate whole CPU proportionally to elapsed phases or subtract elapsed spans to invent phase CPU. Every fitted response must be reconstructible from raw usage endpoints/per-PID wait4 receipts with process-tree/scope assertions.

Before any timing, the later written review must freeze the following measurement contract: workload matrix, repetitions/batch sizes/order, phase masks and Q semantics, feature scalings, exact rational rank check, coefficient objective/tie rule, timer allowance, admissible domain and structural-versus-repeat holdout keys. These are **blocking prerequisite inputs**, not implementer discretion. No fit is presently selected/approved; this draft proposes only the accounting direction. Once that contract is approved, decision order is deterministic: reject missing coverage; reject rank-deficient retained columns; fit the declared nonnegative domination problem; reject any training constraint violation; freeze coefficients; open holdouts; reject any phase/process/end-to-end underprediction before4×. No automatic merging of confounded columns: masks/group mergers require a new prospective review before measurements. Repetition holdouts only test timing repeatability; structurally withheld authorized configurations/byte/event boundaries test coverage and must be separately identified. If a required structural holdout is unavailable, no full-campaign forecast. No favorable row deletion, post-holdout tuning, percentile bound or retrospective tolerance. Nonlinear residuals or unexplained geometry/branch differences require a newly reviewed contract; keep failed evidence.

Use a separate elapsed-wall envelope for durable storage/backend/host effects. Use the inclusive CPU* defined above. Let `IO*` sum wall envelopes for actual write/flush/fsync/directory-sync/read/hash sequences on the intended filesystem, over their bounded byte/file/event counts. Let H be a predeclared nonnegative allowance envelope `h0+hN·N+hQ·Q+hS·S+hV·V+hF·F+hD·D` for scheduling/non-IO stalls, evaluated on full campaign counters and calibrated against whole end-to-end batches under a specified admissible host-load range, and T be separately bounded campaign setup/closure/postflight wall where CPU coverage alone is insufficient. Proposed forecast:

`W_guarded = 4 × (CPU* + IO* + H + T)`.

Overlap between CPU and inclusive IO/T may be conservatively charged twice and must be declared. Never silently subtract CPU from wall to infer IO. Whole supervised holdouts must also be covered before the margin; unexplained residual wall is a coverage failure. Finite repeated wall samples do not bound arbitrary future stalls. Backend/mount/filesystem/free-space policy, host load range and H/T calibration remain unresolved until a reviewed plan supplies concrete rules. If the intended host cannot meet that declared domain, fail closed. Record external load and context switches; serialize own build/test/profile/review jobs outside timing. Revalidate drift before preparation/admission; a backend/source/runtime/load change invalidates reuse.

Activation blockers must be resolved in a reviewed plan before any calibration receipt: (a) backend/mount/filesystem, free-space and host-load eligibility with numerical rejection thresholds; (b) coefficient/IO/H/T derivation and drift rule; (c) direct whole-supervisor holdout wall from before `_inputs` through final return/terminal publication, plus separately charged outer launch/teardown; (d) worst-input parent/child RSS lifetimes and overlap; (e) bounded retained evidence packing. Current supervisor start occurs **after** `_inputs`, so current monitor wall cannot silently stand in for this wider preparation forecast window. Preserve its operative monitor contract unchanged. Unknown numerical domain/threshold/scope means unavailable. Future chosen thresholds require written review, not an implementer-selected safety factor.

The current authorized domain is exactly sixteen construction cases at seeds 7/8, with fixed configurations from `_fixture_arms`; synthetic no-Engine manifest/byte/source fixtures are already separate. Their configurations are tiny 1v1/2v1, E at N=64 and C at N=256, both geometries, dt=1/64. They do not automatically span timestep/rate/profile/actor-band/casualty/byte/sync interactions of the full roster. Repeated fixed cases and existing synthetic probes may be designed for later authorized measurement; additional supplied-state/synthetic engineering fixtures need separate user authorization and predeclaration. Coverage failure with the permitted set is an acceptable blocked outcome. No sampled histories, registered seeds, scientific outcome previews or new entropy draws are permitted for calibration.

## Memory, evidence and admission

Keep one worker, 43,200 s supervised wall, 2,147,483,648 bytes RSS and 4,294,967,296 bytes total uncompressed archive. Preserve row/start/audit/metadata limits, early monitor checks, acknowledged prefix and failure semantics. Stop leaves the planned population incomplete; it is not a native horizon or a replacement-seed opportunity. Complete census/source/accounting/original-byte validation remains required for every outcome and all audits.

Preserve the current **individual collector-child** RSS cap/monitor interpretation and existing floor `ceil(4×peak_probe_RSS +256MiB)`. Neither max across separate probes nor child wait4 establishes simultaneous parent+child memory. Add a separately reviewed combined-memory readiness criterion without redefining the existing monitor: measure/bound parent peak during full manifest/receipt/source/archive parsing and publication, every child lifetime/peak and overlap. A conservative sum of individually certified lifetime peaks can upper-bound overlap; sparse instantaneous samples alone cannot certify peaks. Combined readiness threshold and measurement/error allowance remain blocking reviewed inputs, never an implicit replacement2GiB cap. Require worst-input parsing/validation, source/file/metadata and bounded-block coverage. CPU savings/private wrapper peaks cannot establish RSS neutrality; unknown scope fails closed.

Choose bounded **self-contained retained evidence packs**, rather than unbounded external files. The later v2 plan must define a packing manifest assigning every raw measurement cell (including failures), command/stdout/stderr, identities/process/load snapshots, raw usage endpoints/counters, train/holdout membership, coefficients and independent computation inputs to at most32 fixture-probe artifact slots, each ≤16MiB, plus the already budgeted forecast-inputs resource file ≤16MiB. Packs use bounded strict structured records with explicit length/array/file/count fields; nesting/escaping and reread work must be certified. No omission of raw evidence in favor of asserted summaries. If the matrix cannot fit, calibration is unavailable pending a newly reviewed smaller design; do not add archive slots, consume protected failure reserve or enlarge caps.

Before implementation/activation, an independent complete-wire packing proof must reconcile the current [schema algebra](../../../survey/war1_study/resource_proof.py): ≤32 probes within its43+9 bounded metadata files, ≤4096 source files/64MiB, all reserved descriptor/root files, source/provenance copies, total1GiB metadata allowance and4GiB archive ceiling. Count bytes/file/events for each packing read/copy/revalidation pass. The current [supervisor](../../../survey/war1_study/supervisor.py) copies a closed receipt set and1–32 probe artifacts; adding a v2 field does not make an arbitrary artifact reachable. Future versioned dispatch must retain the same bounded slots or explicitly map v2 packs into those slots with checked descriptors. This required mapping/proof is an activation blocker, not a claim the current dispatcher already supports v2.

New versioned calibration-input/forecast/resource/preseed schemas must bind protocol/roster/manifest, source closure/inventory, binary, toolchains/dependencies/runtime/target/flags, host/backend/parameters and the packing manifest. Independent no-simulator recomputation opens all retained raw packs, checks hashes/bounds/census/coverage/rank/approved fit and holdout policy, then recomputes every forecast component. Scoped dispatch preserves historical v1 saved-archive validation under its existing validator; only v2 admission requires the exact v2 set and rejects v1/unknown/mixed inputs, drift or unavailable evidence. Old failed v1 evidence remains readable and cannot be relabeled as passing v2. Field spellings are later implementation detail; bounds, raw availability and version behavior are required review decisions.

A passing engineering forecast is only resource evidence. Source binding, numerical checks, independent prospective scientific acceptance and exact-workload execution authorization remain distinct. Current readiness is unchanged and no <12 h result is promised.
