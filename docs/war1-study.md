# Prospective W1-A tooling

The separate `war-studies` feature builds `war1-study`. Software preparation and
prospective activation are separate. This document describes tooling; it records
no scientific histories or research results. The fixed population remains
66 arms and 52,224 histories, with explicit execution approval pending.

The [approved design](superpowers/specs/2026-10-10-war-1-measurement-design.md)
and [resolved roster](superpowers/specs/2026-10-10-war-1-measurement-proposal.json)
remain authoritative. The existing engineering `war1` interface and its
`registered:false` outputs retain their original meaning.

From the repository root, the standalone forms are:

```text
python3 -m survey.war1_study prepare --root ROOT --out-dir NEW_DIR
python3 -m survey.war1_study freeze --root ROOT --manifest FILE --out FILE
python3 -m survey.war1_study build-receipt --root ROOT --manifest FILE --inventory FILE --binary FILE --command-file FILE --out FILE
python3 -m survey.war1_study declare --build FILE --numeric FILE --resources FILE --out FILE
python3 -m survey.war1_study analyze --campaign DIR --manifest FILE --oracles FILE --out NEW_DIR
```

Preparation requires the independently checked construction resource bundle at
`survey/war1_study/preparation/preseed-resource-readiness.json`. Its producer is
`prepare_evidence(root, fixture_binary, fixture_binary, fixture_manifest, out)`
with `out` equal to that excluded preparation directory. This runs only the
16 fixed construction cases at seeds 7/8, full synthetic manifest/byte workloads,
and pure arithmetic. It verifies release metadata and the complete escaped
schema proof, measures actual executed actor work, and applies a fourfold
forecast margin to the full 2,054,160,384 actor-step and 52,224-start/outcome
population. Source copying/validation, projection, audit synchronization and
constructor/terminal work and start/outcome synchronization remain separate costs. Unavailable or excessive
forecasts block sampling. A forecast is conditional on hardware/filesystem
behavior; it never replaces monitored hard limits.

After software review and exact-commit CI, `prepare` draws each u64 independently
with `os.urandom(8)`, retaining duplicate values. It creates one raw manifest at
`NEW_DIR/manifests/frozen-<raw SHA256>.json`; that filename is absent from its
content. A failed/existing destination cannot silently redraw. Commit the exact
manifest under `survey/war1_study/manifests/` before scientific compilation:

```sh
WAR1_STUDY_MANIFEST=survey/war1_study/manifests/frozen-HASH.json \
  cargo build --manifest-path survey/Cargo.toml --locked --release \
  --features war-studies --bin war1-study
```

Keep the fixture executable separately. `metadata`, `validate --manifest FILE`
and `numerics --manifest FILE --out NEW_FILE` construct no Engine. Use only those
commands on a scientific executable during preparation. The no-argument/help
native output lists the supported forms. Native `fixture --manifest FILE --out
NEW_DIR` is construction-only; scientific `collect --declaration FILE --acceptance
FILE --execution FILE --out NEW_DIR` also requires the supervisor's private local
control channel. Invoke collection through
`preparation.supervise(command_tuple, out, 43200, 2147483648)` only after actual
independent review and explicit exact-population owner authorization. There are
no approval, resume, retry or override flags. Exit codes are 0 success, 2 invalid
input/usage/preflight and 1 execution/output failure.

The fixed packet uses `build.json`, `numeric.json`, `resources.json`,
`source-inventory.json`, and `freeze-context.json` siblings. The command file is
an object with exactly `command`, an array containing the complete build argv.
Build receipts bind actual executable bytes, selected inputs, toolchain/features/
flags and unchanged inventories. `prepare_evidence` with the scientific binary
then emits certified exact-law numeric and resource receipts. Declaration
creation verifies those raw packet bytes again. Neither readiness acceptance nor
execution permission is generated by software.

`normative_frozen_revision` names the committed source/manifest freeze.
`declaration_revision` names the distinct actual preparation-receipt HEAD at
declaration creation (its base revision). The later commit containing the
declaration is recorded externally in the handoff; it cannot contain its own
Git SHA. Receipt/declaration files, preparation outputs and unselected manifests
are excluded from compiled inputs. All local Python study sources and native
collector sources remain included. Selected sources are bounded at 4096 files,
16 MiB each and 64 MiB total. Scientific and fixture builds must have identical
normative inputs except for their selected manifest path/bytes. The shared sorted
`fixtures/core-literal-inputs-v1.txt` also binds all 229 external literal core
inputs; an independent Python audit checks the actual include expressions.
Imported build-support sources are included without modifying their selectors.

One worker is limited to 2 GiB RSS, 12 hours and 4 GiB uncompressed campaign bytes.
The complete-row proof reserves 1,764,753,408 bytes for starts/outcomes,
778,240,000 bytes for fixed audits, and 1 GiB for source/provenance, metadata,
leftovers, bounded logs and failure/publication reserve: 3,616,735,232 bytes total.
Runtime row/file/output gates still apply before writes. The supervisor polls
elapsed time and active RSS at intervals no greater than 0.1 seconds, retains only
bounded progress/logs, and obtains the individual child's final peak with
`os.wait4` (macOS bytes, Linux KiB). It validates source, receipts, candidate
archive and final peak before create-only synchronized `monitor.json` and
`success.json`. A candidate alone is provisional. Abrupt termination has null
final physics clocks/checkpoint and separately labeled last-progress samples;
a cooperative native failure retains its actual clocks and durable prefix.

Compact rows contain four observations and final checkpoints. They and semantic
transcript hashes are not lossless full-frame archives. Only replicate index 0
of every arm has all raw audit frames. A missing or invalid planned outcome
makes primary ensemble inference unavailable; no seed replacement or smaller
successful-only denominator is allowed. Reference unavailability affects its
comparison endpoint while preserving finite outcomes. Actual final-step
extinction and administrative censoring both place restricted duration at the
horizon and remain explicitly distinguishable.

The scalar family has 924 slots and the CDF family 198 slots. At 512 replicates the
simultaneous scalar radius is approximately 10.5 percentage points; small
near-equality contrasts may remain unresolved. Tiny-law comparisons distinguish
stored native probability p, realized dyadic q and mathematical p*. Exact-q
propagation uses normalized interval widths at most 1e-10, native p must fit the
four-ULP criterion, and the finest one-versus-one discrete/continuous comparison
requires each specified margin at most 0.02. Neither compatibility nor
nonrejection proves RNG independence or general continuous-time agreement.

Analysis reads saved bytes only, creates a fresh report directory, and preserves
all registered estimates, contrasts and availability decisions. Construction
panels remain unregistered and have no scientific sampling bands or conformance
verdicts. Publication and scientific collection require their separate approvals.
